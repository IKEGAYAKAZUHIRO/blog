エゴサーチで出なかった

このサイトは2026年10月くらいからつくり始めたものだが、それには理由がある。

検索ルールがいつの間にか変わり、自分の名前（漢字）でエゴサーチしても自分の名前が一切出なくなっているのに気付いたのだ。名字の読み方だけ違う同姓同名の作家の方がおられ、検索結果には彼の著作が並ぶ。

あんまりエゴサーチってやってなかったんだけど、この状況が急に面白くなり、検索結果に僕の名前を1個出す、という目標を立てた。50代後半男性自意識の目覚め。同姓同名氏と面識はないものの、なるほどそれは敵わないですねという文化人であり、現状には深く納得している。悪いのは僕の人徳のなさである。

いずれ検索はAIエンジンに取って代わるだろうからサイトにはAI向けデータを入れまくることにした。

AIの説明：AI対策としてやったこと

表　AI向けに置いたもの

置いたもの中身狙い
robots.txtすべてのクローラーを許可。Content-Signal の行で、検索・AI の回答・学習のどれに使ってもよいと示すAI に読みに来てもらう
llms.txtAI 向けの案内文。サイトの性格、件数の読み方、同じ漢字の別人への注意を書く。全記事の一覧は llms-full.txt に分けた最初に読む1枚で誤解を防ぐ
記事の Markdown 版各記事に、飾りの無い本文だけの版を付ける余計な HTML を読ませない
JSON-LDページに埋め込む機械向けのデータ。書き手、元の記事の媒体・発行元・URL、関わり方を入れる「誰が何を書いたか」を推測させない
index.json実績の全件を1つの JSON にまとめたもの一覧を丸ごと渡す
Wikidata の項目本人と著書の項目。読み・生年・職業を出典つきでAI や検索が人物の見分けに使うデータに載せる

※ 作業記録から。

気を配ったのは3点。

1つめは、サイトに書かれているのは同じ人だと機械に分かるようにすること。名刺、実績の一覧、ブログの書き手のデータに同じ ID を振り、X、日経クロステックの著者ページ、Wikidata の項目へのリンクを並べた。ばらばらのページが同一人物にまとまる。

2つめは、同姓同名氏とは別人だと機械に分かるようにすること。JSON-LD には見分けのための説明を書く欄（disambiguatingDescription）があり、そこに読み・分野・生まれと、同じ漢字の方とは別人であることを書いた。llms.txt にも「経歴と著作を混ぜないでほしい」という節を置いた。人が読むページには、名刺の一番下に小さく書いた。

3つめは、書いていないものを書いたと誤認させないこと。実績には、執筆のほかに共同執筆、特集への参加、制作担当がある。機械向けのデータでは、自分が書いたものだけを著者とし、特集への参加や制作担当は「協力者」として関わり方を添えた。

まだ効果は出ていない

作業から2週間ほど経ったが、公開から間もないこともあり、効果は確認できない。

チャットAIでsite:ikegaya.tokyoを解説させるとビックリするくらい情報が出てくるようにはなった。構造化データの使われ方の勉強になったので、目的はまだ達成されてないがトライとしては十分な成果を得た。
