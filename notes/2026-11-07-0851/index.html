AIに仕事させる方法、分からん

僕の実績記録をまとめたサイトは全投稿がClaude codeによる自動生成だ。こういうのをサクサクやるにはAIの動かし方の基本みたいなのがあるなど思って、投稿にしてみる。将棋に7六歩があるように、AIにも初手というものがありますよ、というお話し。

環境づくりの手順をAIがまとめる

AI の自動処理は Python で動く

いきなりですが、Claude Code が claude.ai のチャットと違うのは、話すだけでなく、PC の上で実際に作業することです。Claude Code はその場で小さなプログラム（スクリプト）を書いています。「Excel の表を 30 枚まとめて集計して」と頼まれたら、30 枚を一枚ずつ開くのではなく、集計するスクリプトを書いて 1 回で済ませます。

そのスクリプトの多くは、Python というプログラムの言語で書きます。つまり、AI に自動で仕事をさせるというのは、チャットを使って「Python を操作してもらう」ということです。

Windows には Python が最初から入っていません。Claudeアプリと同時に入れるのがオススメです。Claude Code に「Python を入れて」と頼んでください。

フォルダを決める

Pythonを使う空間として、アプリ起動時にまずClaude Code が読み書きするフォルダを 1 つ作って指定します。場所はたいていどこでも構いませんが、OneDrive などの同期フォルダの中は避けてください。C:\work\ のように、同期されない場所が安全です。

続けて「このフォルダに CLAUDE.md を作って」と頼むと、フォルダの中に CLAUDE.md という名前のファイルができます。Claude Code が起動のたびに最初に読む「申し送り」です。何か始める前にこれをつくっておくとスムースです。ここで何をするつもりかを短くメモ書きしておきます。

これは起動時や新しい指令を受けたときなどに毎回読まれるので、短く保ちます。「100 行以内」「長い説明は別のファイルへ」という決まりもあると良いです。そこで、次のような文面をコピペさせます（アプリを1回閉じて、自分でコピペしても構いません）。

# このフォルダについて

仕事の資料と、Claude と一緒に調べたこと・決めたことを置くフォルダ。

## 決まり

- 応答はすべて日本語で
- 調べたこと・決めたことは docs/ に Markdown で書く。会話が終わっても次に続けられるように
- この CLAUDE.md は 100 行以内。長い説明は docs/ に分けて、ここには場所だけ書く
- ファイルを消す前・外に送る前（メール・公開）は聞く
- 直したら git でコミットする（メッセージは日本語）

## どこに何があるか

作業の前に、話題に合うファイルを下の表から探して読む。docs/ にファイルを足したら、この表に 1 行足す。

| 話題 | ファイル |
|---|---|
| 月次の報告の作り方 | docs/monthly-report.md |
| 取引先の一覧の決まり | docs/clients.md |

最初はこれくらいで足ります。あとは作業のたびに、Claude Code が docs/ と表を書き足していきます。

.claude というフォルダについて

Claude Code を起動すると、ユーザーフォルダに .claude というフォルダができます。CLAUDE.md と名前は似ていますが、役目も置き場所も違います。Windows を例に取るとこうなります。

C:\Users\あなたの名前\              ← Windows のユーザーフォルダ
└─ .claude\                        ← どの仕事にも効く設定
    ├─ settings.json
    └─ CLAUDE.md                   ← どの仕事にも共通のお願い（無くてよい）

C:\work\                           ← 上で決めた仕事のフォルダ
├─ CLAUDE.md                       ← この仕事のお願い（上で置いたもの）
├─ docs\                           ← 調べたこと・決めたことのファイル
└─ .claude\                        ← この仕事だけの設定
    └─ settings.local.json         ← 「常に許可」を押すとここにたまる

ややこしいのは、図のとおり .claude の中にも CLAUDE.md があることです。ここが一番の混乱のもとです。「CLAUDE.md を直して」と頼んだつもりが、別の場所の CLAUDE.md が直っていた、ということが起きます。

  • ユーザーフォルダの .claude\CLAUDE.md は、どの仕事のフォルダで起動しても読まれます
  • 仕事のフォルダの CLAUDE.md は、そのフォルダで起動したときだけ読まれます

なので、仕事ごとの決まりは仕事のフォルダの CLAUDE.md に書き、どの仕事でも変わらないこと（「応答は日本語で」など）だけをユーザーフォルダの .claude\CLAUDE.md に書きます。迷ったら仕事のフォルダのほうへ。

やってはいけないことは、CLAUDE.md に書くより .claude の設定で止めます。

Git は必須

仕事のフォルダは Git（変更履歴の帳簿）で管理します。これは省けません。Git が帳簿をつけるひとまとまりをリポジトリ（略してリポ。「貯蔵庫」の意味）と呼びます。

始め方は、Windows なら Git for Windows を入れておき、フォルダを決めたら Claude Code に「このフォルダを git で管理して」と頼むだけです。外部サーバーへも同期でき、その代表例がGitHubです。

  • Claude Code が書き換えたファイルを、いつでも前の状態に戻せます。AI は人間と同じかそれ以上にトライアンドエラーを繰り返すので、間違えたときの戻り道が要ります
  • 「いつ・何を・なぜ変えたか」が残ります。次に起動した Claude Code も、それを読んで続きができます

結論：けっこう便利よ

GitはLinuxの創世神リーナス・トーバルズ氏がカーネルの更新のためにつくった伝説的なアプリで、この仕組みを使って「何かやったら記録する」というワンアクションを組み込むのがAIを使うスタートラインですよ、というのがこの投稿の本旨となる。記録が混ざらないように、仕事の種別ごとに新しいフォルダを用意していくのがベストだ。

僕の実績記録サイトはこういう環境の中で試しにつくらせては壊しを何回転かやってコンセプトを固めたものだ。やはりいろいろ試してるとアイデアが出てくるものなのだ。サーバサイドの整備はちょっと面倒なのでまた今度にしておく。

ちなみに、Claude codeの使い方を他の無料で使えるチャットAI（ChatGPTやGemini、Qwenなど）に聞くと、やたら詳しく教えてくれてだいたい合っている。なぜならAnthropicがドキュメントを大量に公表してるからだ。僕のこの初手ももちろん、AIに聞いて試したものである。
