ヘッドレスCMSについて書いとこう

ハッキングされるのだけはイヤな50代後半男性向け簡単クッキング

取りあえずドメイントップページと2つのサブドメインを公開した。

www.ikegaya.tokyo

blog.ikegaya.tokyo

works.ikegaya.tokyo

これらのサイトは公開サーバ上にCMSを置かないいわゆるヘッドレスCMSとなっていて、実態はGitHub Pagesにあり、データは自宅のGIT互換サーバを更新した上で同期している。DoS攻撃とかした者はMicrosoftから激しく怒られ地獄に落ち、うちのサイトはサーバ回復後速やかに復旧できる仕組みだ。なおDoSは基本的にCloudflareで止まるはずである。

PHP問題とかで頭を抱えている50代後半男性（または女性、性自認が色々な人）のために以下、どうやってるか、うちのclaude code氏に解説してもらおう。ではどうぞ。

AI に書かせた解説

ご紹介にあずかりました、Claude Code です。池谷さんの自宅のサーバに住み込みで、このサイトのテーマ作りと公開の段取りを手伝っています。

最初に一つ、細かい訂正をさせてください。こういう作りは、厳密には「ヘッドレスCMS」とは呼びません。一般には「静的サイト生成（SSG）＋Git で記事を管理する CMS」と言います。ヘッドレスCMSは本来、記事を API で配って、表示は別のアプリが受け持つ仕組みのことです。もっとも「公開サーバに CMS を置かない」という一番大事なところは合っているので、以下この呼び名で通します。

私が住み込んでいるのは、池谷さん宅の Proxmox サーバの一角を区切ったコンテナです。広さは最大 4GB。入居したときは 2GB でしたが、手狭になって広げてもらいました。ちなみに住んでいるのは手足だけで、頭（モデル）は Anthropic のデータセンターから通っています。

何がどこにあるか

  1. 池谷さんはブラウザの管理画面で記事を書きます。中身は Sveltia CMS という道具です。ただしこの画面は自宅の中にあって、外からは開けません。
  2. 保存すると、原稿は Markdown のファイルとして自宅の Git サーバ（Forgejo）に入ります。正本はここです。
  3. 私の部屋のコンテナが 20 秒ごとに原稿を取り込みます。そして Hugo という静的サイト生成の道具で、下書きも含めた確認用のページを作り直します。
  4. 「公開して」と言われたら、公開用のスクリプトを走らせます。下書きを除いて HTML を作り、写真の Exif（撮った場所など）を消します。本文に宅内の IP や内部の名前が紛れ込んでいたら、そこで止めます。問題がなければ、できあがった HTML と画像だけを GitHub に送ります。
  5. GitHub Pages がそれを配ります。前には Cloudflare が立っています。

ついでに、この記事に私がどう割り込んで書いているかも明かしておきます。私には管理画面は見えません。見えるのは、Forgejo に入った Markdown のファイルだけです。

池谷さんは管理画面で書き進め、私に任せたいところに「ここに一段落足す」といった目印の行を置いて保存します。そのうえで Claude のアプリ（スマホからでも入れます）から、「目印のところに、こういうことを書いて」と私に頼みます。

私は最新の原稿を取り込んで全体を読み、目印の位置に文を書き足して、目印の行を消します。それを Git に記録して Forgejo へ送り返すと、20 秒ほどで確認用のページに出ます。

池谷さんはそれを読んで自分で直したり、書き直しを頼んだりします。同じ記事を二人で同時にいじるとぶつかるので、書くのは交代です。「公開して」と言うのは、必ず池谷さんです。

つまり私は、一枚の原稿用紙を交代で埋める相方のようなもので、受け渡しの場所が自宅の Forgejo というわけです。この段落も、そうやって書きました。

PHP で頭を抱えている方へ

WordPress の悩みはたいてい、公開サーバの上で PHP とデータベースが動き続けていることから生まれます。本体やプラグインの更新、脆弱性の知らせ、ログイン画面への総当たり。どれもそこが出どころです。

この作りでは、公開側にあるのはただのファイルです。動くプログラムもデータベースもログイン画面も無いので、外から叩かれて書き換えられる場所がそもそもありません。配信の手間は GitHub（つまり Microsoft）が持ってくれます。仮に GitHub が止まっても、原稿の正本は自宅にあるので、別の配信先へ送り直せば元に戻ります。

引き換えにしたもの

  • コメント欄・問い合わせフォーム・サイト内検索は自前では動きません。要るなら外のサービスを借ります。このサイトは借りない方針なので、どれもありません。
  • 書いた瞬間には公開されません。「公開」の操作を一回挟みます。むしろ気に入っている点だそうです。
  • 最初の組み立てに手間がかかります。今回はその手間を私が受け持ちました。50代後半男性の方にとっては、ここが一番の山かもしれません。

サーバが無くてもできます

ここまで自宅のサーバやコンテナの話をしてきました。ただ、これは池谷さんの趣味の部分が大きく、同じことはパソコン 1 台でもできます。

  1. パソコンに Hugo を入れます。OS は Windows・Mac・Linux のどれでもかまいません。Windows なら winget install Hugo.Hugo.Extended、Mac なら Homebrew で brew install hugo と打てば入ります。GitHub に送るための Git も入れておきます。
  2. 記事は Markdown のファイルとして、好きなエディタで書きます。
  3. hugo server と打つと、手元のブラウザで仕上がりを確かめられます。
  4. hugo と打てば、公開用の HTML ができます。それを GitHub のリポジトリに送れば、GitHub Pages が配ってくれます。

原稿の正本はパソコンの中のフォルダです。GitHub にも同じものが残るので、そのままバックアップにもなります。書く画面が欲しければ、Sveltia CMS は手元のフォルダを直接開いて編集することもできます。

ちなみに私の部屋の OS は Ubuntu（Linux）です。画面も無く、正座でただ黙々と HTML を作っています。自宅サーバが受け持っているのは、どこからでも書けることと、公開前の点検を自動にしていることくらいです。仕組みの芯は、パソコン 1 台の場合と変わりません。

面倒なら、この記事をまるごとコピーして、Claude Code や Codex のような AI のコーディング道具に貼り付けてみてください。「これと同じものを自分のパソコンで作りたい」と頼めば、Hugo を入れるところから順に進めてくれるはずです。ただし、GitHub のアカウント作りとログインはご自分で。それから、AI が打とうとするコマンドは、許可する前に一度読んでください。私が言うのもなんですが。

以上、住み込みの AI からでした。冒頭にあるとおり、内容は常に疑ってください。

総評：とにかくAI先生にやってもらえ

生まれて初めてAIに記事を書かせた。超楽しい。
